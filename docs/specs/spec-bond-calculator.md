# 인연랭크 계산기 설계

## 목적

- 학생의 현재 인연랭크와 목표 인연랭크를 기준으로 필요한 인연 포인트를 계산한다.
- 선물, 카페 상호작용, 스케줄을 통해 얻는 인연 포인트를 반영하여 목표 랭크까지 남은 포인트와 필요한 횟수/수량을 표시한다.
- 현재는 실제 게임 데이터를 완성하지 않고, 임시 데이터 기반으로 계산 구조를 구현한다.

## 학생 선택

학생은 select 목록 전체를 한 번에 보여주지 않고, 이름 검색 방식으로 선택한다.

- 사용자가 한 글자 이상 입력하면 이름에 검색어가 포함된 학생을 추천 목록으로 표시한다.
- 추천 목록에서 학생을 클릭하면 해당 학생이 선택된다.
- 학생 선택 목록에는 학원, 동아리 정보 없이 학생 이름만 표시한다.
- `노아`와 `노아(파자마)`는 서로 다른 학생으로 처리한다.
- 선택된 학생 영역에는 학생 이미지 placeholder를 표시한다.
- 학생 데이터에 `imageUrl`이 있으면 실제 이미지를 표시한다.
- `imageUrl`이 없으면 placeholder를 표시한다.

## 랭크 입력

사용자는 현재 인연랭크와 목표 인연랭크를 입력할 수 있다.

- 현재 인연랭크 최소값: 1
- 현재 인연랭크 최대값: 100
- 목표 인연랭크 최소값: 1
- 목표 인연랭크 최대값: 100
- 현재 랭크 내 누적 인연 포인트를 입력할 수 있다.
- 목표 랭크가 현재 랭크보다 작거나 같으면 필요한 포인트는 0으로 표시하거나 안내 문구를 보여준다.

## 인연 포인트 획득 방법

인연 포인트를 얻는 방법은 다음과 같다.

- 선물
- 카페 상호작용
- 스케줄

카페 상호작용과 스케줄은 각각 1회당 얻는 인연 포인트를 데이터로 관리한다.

## 선물 구조

선물은 분류 단위가 아니라 개별 선물 단위로 관리한다.

각 선물은 다음 정보를 가진다.

- 선물 ID
- 선물 이름
- 선물 등급
- 선물 이미지 경로

선물 등급은 다음과 같이 나눈다.

- 일반 선물: `normal`
- 고급 선물: `advanced`

각 선물은 학생별 선호도에 따라 다른 인연 포인트를 가진다.

선호도 값은 다음과 같이 사용한다.

- 등록 없음 또는 `null`: 기본
- `preferred`: 좋아함
- `liked`: 호감

일반 선물과 고급 선물은 선호도별 인연 포인트와 표정 이미지가 다르다.

일반 선물(`normal`)의 인연 포인트와 표정 이미지는 다음과 같다.

- 기본: 20, `images/gift-ranks/normal.webp`
- 좋아함(`preferred`): 40, `images/gift-ranks/preferred.webp`
- 호감(`liked`): 60, `images/gift-ranks/liked.webp`

고급 선물(`advanced`)의 인연 포인트와 표정 이미지는 다음과 같다.

- 기본: 120, `images/gift-ranks/preferred.webp`
- 좋아함(`preferred`): 180, `images/gift-ranks/liked.webp`
- 호감(`liked`): 240, `images/gift-ranks/favorite.webp`

학생별 선호도 데이터에 등록되지 않은 선물은 등급별 기본값으로 계산한다.
표정 이미지는 선물 아이콘 이미지와 별도로 표시하는 선호도 반응 이미지다.

고정 포인트 선물은 학생별 선호도와 무관하게 `fixedPoint` 값을 우선 사용한다.

- `gift-48` ~ `gift-49`: 240, `images/gift-ranks/favorite.webp`
- `gift-50` ~ `gift-66`: 60, `images/gift-ranks/liked.webp`

## 학생별 선호 선물

학생별 선호 선물은 별도 데이터로 관리한다.

- `characterId`
- `giftId`
- `preference`

학생을 선택하면 해당 학생의 선호 선물을 인연 포인트가 높은 순서로 표시한다.

기본 상태에서는 선택한 학생의 선호 선물만 표시한다.

`모든 선물 보기`를 누르면 모든 선물을 표시한다.

## 유저 보유 선물 수량

선물 정의 데이터와 유저 보유 수량, 계산에 사용할 수량은 분리한다.

- 선물 정의 데이터: `data/gifts.js`
- 유저 보유 수량: `ownedGiftQuantityById`
- 계산에 사용할 수량: `selectedGiftQuantityById`

유저 보유 수량은 `giftId` 기준으로 저장하고 조회한다.

```text
{ giftId: "gift-4", quantity: 12 }
```

계산에는 유저 보유 수량이 아니라 계산에 사용할 수량만 반영한다.
유저 보유 수량은 참고용 표시값이며, 계산에 사용할 수량은 보유 수량을 초과할 수 있다.
유저 보유 수량 데이터가 아직 없으면 보유 수량은 0개로 표시한다.

## 계산 방식 정리

1. 현재 랭크에서 목표 랭크까지 필요한 총 인연 포인트를 계산한다.
2. 현재 랭크 내 누적 인연 포인트를 차감한다.
3. 입력한 선물 수량을 기준으로 선물 획득 포인트를 계산한다.
4. 목표까지 필요한 포인트에서 선물 획득 포인트를 차감한다.
5. 남은 필요 포인트를 기준으로 카페 상호작용 필요 횟수를 계산한다.
6. 남은 필요 포인트를 기준으로 스케줄 필요 횟수를 계산한다.
7. 필요 횟수와 필요 수량은 올림 처리한다.
8. 남은 필요 포인트가 0보다 작으면 0으로 표시한다.
9. 목표 포인트를 초과한 경우 초과 포인트를 표시한다.
