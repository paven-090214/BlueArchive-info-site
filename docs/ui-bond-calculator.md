# 인연랭크 계산기 UI

## 목적

- 학생의 인연랭크 목표값을 계산한다.
- 실제 게임 데이터를 완성하지 않은 상태에서도 임시 데이터와 구조 중심 계산을 검증한다.
- 학생 검색, 개별 선물 카드, 카페 상호작용, 스케줄 필요 횟수를 한 화면에서 확인한다.

## 전체 배치

- 상단은 2분할로 구성한다.
- 왼쪽에는 학생 검색/선택, 선택한 학생 이미지, 현재 인연랭크, 목표 인연랭크, 현재 랭크 내 누적 인연 포인트, 카페/스케줄 1회 포인트를 배치한다.
- 오른쪽에는 계산 결과 요약을 배치한다.
- 선물 목록은 상단 영역 아래에 넓게 배치한다.

## 학생 선택 방식

- 학생 전체 목록을 select 옵션으로 한 번에 보여주지 않는다.
- 학생 이름 검색 입력창에 한 글자 이상 입력하면 추천 목록이 나타난다.
- 추천 목록은 이름에 입력값이 포함된 학생만 보여준다.
- `노아`를 입력하면 `노아`, `노아(파자마)`가 함께 표시된다.
- 추천 항목을 클릭하면 해당 학생이 선택된다.
- `노아`와 `노아(파자마)`는 서로 다른 캐릭터로 취급한다.
- 선택한 학생 영역의 왼쪽에는 학생 이미지 placeholder 또는 실제 이미지를 표시한다.
- 학생 데이터에 `imageUrl`이 있으면 이미지를 표시하고, 없으면 placeholder를 표시한다.

## 입력값

- 학생 이름 검색
- 현재 인연랭크
- 목표 인연랭크
- 현재 랭크 내 누적 인연 포인트
- 카페 상호작용 1회 포인트
- 스케줄 1회 포인트
- 랭크별 필요 EXP는 `data/bond-rank-requirements.csv`를 기준으로 만든 JS 데이터를 사용한다.

## 선물 목록 구조

- 선물은 개별 카드 형태로 표시한다.
- 기본 상태에서는 선택한 학생의 선호 선물만 보여준다.
- `모든 선물 보기` 버튼으로 전체 선물 목록을 확인할 수 있다.
- `선호 선물만 보기` 버튼으로 다시 학생별 선호 선물로 돌아갈 수 있다.
- 선물은 해당 학생에게 주는 인연 포인트가 높은 순서로 정렬한다.
- 선물 목록은 넓은 그리드로 배치해 카드가 여러 열로 보이게 한다.
- 선물 카드에는 다음 순서로 표시한다.
  1. 선물 이미지 placeholder 또는 실제 이미지
  2. 획득 인연 포인트
  3. 수량 조절 영역
  4. 선물 이름은 카드 본문에 크게 노출하지 않고 tooltip으로 확인한다.
- 선물 카드에는 `title`과 `aria-label`을 둬서 전체 이름을 확인할 수 있게 한다.
- tooltip은 카드 바깥쪽에 표시해 포인트 숫자와 이미지를 가리지 않도록 한다.
- tooltip에는 선물 이름과 등급, 선호도, 인연 포인트를 함께 보여준다.
- 수량 조절 영역에는 `-` 버튼, 수량 입력, `+` 버튼을 둔다.

## 선물 EXP 규칙

### 일반 선물

- 선호도 없음: 20 EXP
- 선호 선물: 40 EXP
- 극선호 선물: 60 EXP

### 고급 선물

- 기본: 120 EXP
- 해당 학생의 선호 선물: 180 EXP

### 고정 EXP 예외 선물

- 아름다운 꽃다발: 240 EXP
- 싱그러운 꽃다발: 240 EXP
- 반짝이는 꽃다발: 60 EXP
- 하츠네 미쿠의 포토카드: 60 EXP
- 선물선택상자: 60 EXP

### 선물 데이터 구조

- 선물은 분류 단위가 아니라 개별 선물 단위로 저장한다.
- `data/gifts.js`는 다음 구조를 사용한다.

```js
{
  id,
  name,
  grade,
  imageUrl,
  fixedPoint
}
```

- `grade` 값은 `normal`, `advanced`, `special` 중 하나다.
- `fixedPoint`가 있으면 학생 선호도보다 우선한다.
- `imageUrl`은 아직 실제 이미지가 없으면 `null`로 둔다.
- `excludeFromPreferredView`가 있으면 기본 선호 선물 보기에서 제외한다.
- 고정 EXP 예외 선물은 기본적으로 선호 선물 목록에 들어가지 않는다.

## 학생별 선호 선물 데이터

- `data/character-gift-preferences.js`에서 관리한다.

```js
{
  characterId,
  giftId,
  preference
}
```

- `preference` 값은 `liked` 또는 `favorite`를 사용한다.
- 학생별 선호 선물만 표시할 때 이 데이터를 기준으로 필터링한다.
- 고정 EXP 선물을 나중에 명시적으로 넣고 싶다면, 해당 학생의 선호 데이터에 직접 등록해야 한다.

## 포인트 계산 구조

1. `currentTotalExp = totalExp[currentRank] + currentRankProgress`로 현재 누적 EXP를 계산한다.
2. `targetTotalExp = totalExp[targetRank]`로 목표 누적 EXP를 계산한다.
3. `requiredExpToTarget = Math.max(0, targetTotalExp - currentTotalExp)`로 목표까지 남은 EXP를 계산한다.
4. 입력한 선물 수량을 기준으로 선물 획득 EXP를 계산한다.
5. 남은 필요 EXP에서 선물 EXP를 차감한 뒤 카페 상호작용 필요 횟수와 스케줄 필요 횟수를 계산한다.
6. 카페는 1회당 15 EXP, 스케줄은 1회당 25 EXP로 계산한다.
7. 필요 횟수와 필요 수량은 올림 처리한다.
8. 남은 필요 EXP가 0보다 작으면 0으로 표시한다.
9. 목표 포인트를 초과한 경우 초과 포인트를 표시한다.

## 결과 영역

- 다음 인연랭크까지 필요한 인연 포인트
- 목표 인연랭크까지 필요한 총 인연 포인트
- 선물로 획득한 총 인연 포인트
- 남은 필요 인연 포인트
- 카페 상호작용 필요 횟수
- 스케줄 필요 횟수
- 초과 포인트

## 임시 데이터

- 실제 게임 데이터는 아직 연결하지 않는다.
- 학생 데이터는 임시 샘플만 사용한다.
- 선물 데이터, 인연랭크 필요 포인트, 카페/스케줄 포인트도 임시 값으로 분리해 사용한다.

## 추후 확장

- 학생별 선호 선물 데이터는 이후 실제 데이터로 교체한다.
- 인연랭크 요구 포인트도 실제 게임 데이터로 교체한다.
- 선물 데이터와 카페/스케줄 포인트도 실제 값으로 갱신한다.
- 학생 이미지, 선물 이미지도 이후 실제 리소스로 교체한다.
